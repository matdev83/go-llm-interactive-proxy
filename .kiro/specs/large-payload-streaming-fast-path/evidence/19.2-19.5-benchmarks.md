## 3. Methodology & Benchmark Harness Design

Four dedicated test suites were implemented in `package frontendpipe_test` under `internal/plugins/frontends/frontendpipe/` matching the baseline structure from Task 1.10:

1. `large_payload_stages_bench_test.go`:
   - Benchmarks each stage across sizes 32 KiB, 256 KiB, 1 MiB, 5 MiB:
     - `BenchmarkLargePayloadStages_Capture` (upload + bounded memory spool / disk spill)
     - `BenchmarkLargePayloadStages_Proof` (`openairesponses.NewProfile().CompileProof`)
     - `BenchmarkLargePayloadStages_Assessment` (`LargeBodyAssessor.AssessLargeBody`)
     - `BenchmarkLargePayloadStages_ProviderOpen` (loopback HTTP POST from replay source)
     - `BenchmarkLargePayloadStages_WireEndToEnd` (full `frontendpipe.ServeHTTP` with wire execution)
   - Benchmarks required body shapes at 1 MiB:
     - Giant string (`{"model":"...","input":"..."}`)
     - Late model (`{"input":"...","model":"..."}`)
     - Tools (function schema + large input)
     - Malformed JSON (syntax error, fast rejection)
     - Canonical fallback (`"store": true` unsupported control key -> fallback under same permit)
     - Replay failover (attempt 1 fail, attempt 2 re-read from replay source)
   - Gated test-only 20 MiB benchmark: `BenchmarkLargePayloadStages_20MiB_WireEndToEnd` (skipped under `-short`, raised `MaxRequestBodyBytes: 32 MiB`).
   - Characterization test: `TestLargePayloadStages_DecodePermitNotHeldDuringUpload`.

2. `large_payload_heap_invariant_bench_test.go`:
   - Measures two distinct heap phases across 1 MiB, 5 MiB, and test-only 20 MiB:
     - `BenchmarkLargePayloadHeap_ProofTimeTransient`: transient allocation during `CompileProof`.
     - `BenchmarkLargePayloadHeap_PostCommitRetained`: total request lifecycle in accepted wire execution.
     - `BenchmarkLargePayloadHeap_RetainedPostProofGC`: isolated retained heap post-proof/pre-wire execution.
   - Characterization test: `TestLargePayloadHeap_AcceptedWireHasNoCallTree`.

3. `large_payload_static_blocker_bench_test.go`:
   - Compares:
     - `BenchmarkLargePayloadBlocker_DisabledBaseline` (`Enabled: false`)
     - `BenchmarkLargePayloadBlocker_LocalTurn` (`Enabled: true`, `PlaneAccessCanonicalRequired` on Local Turn)
     - `BenchmarkLargePayloadBlocker_SecretGuard` (`Enabled: true`, `PlaneAccessCanonicalRequired` on Secret Guard)
     - `BenchmarkLargePayloadBlocker_BelowThreshold` (`Enabled: true`, Content-Length 512 B < 1 MiB threshold)
   - Characterization test: `TestLargePayloadBlocker_ZeroTempFilesAndNoScanner`.

4. `large_payload_concurrency_spool_bench_test.go`:
   - Benchmarks:
     - `BenchmarkLargePayloadConcurrent_AcceptedWire` (`RunParallel` 1 MiB wire requests)
     - `BenchmarkLargePayloadConcurrent_SlowUpload` (slow chunked client stream)
     - `BenchmarkLargePayloadConcurrent_SpoolBudgetSaturation` (tight 2 MiB budget with concurrent 1 MiB requests)
   - Characterization tests:
     - `TestLargePayloadConcurrent_SpoolBudgetIsOptimizationBudgetNotOOM`

`TestLargePayloadStages_DecodePermitNotHeldDuringUpload` verified:
- Upload and spill file I/O execute to completion with **zero decode permits held**.
- The single byte-weighted decode permit is acquired only after upload completion.
- The permit is held across `CompileProof` (~24.4 ms at 1 MiB) and `AssessLargeBody` (~0.6 µs at 1 MiB).

- Total permit hold time on accepted wire requests is strictly bounded by proof + assessment duration, eliminating head-of-line blocking during slow client uploads.

### 5.2 Honest Slope Analysis across 1 MiB → 5 MiB → 20 MiB

#### Phase A: Transient Proof-Time Allocation (`CompileProof`)
- 1 MiB: 6,877,983 B/op (~6.56x body size)
- 5 MiB: 34,141,596 B/op (~6.51x body size)
- 20 MiB: 165,527,723 B/op (~7.89x body size)
- **Slope**: Linear $O(\text{payload})$. As identified in the Task 15.1 review, `CompileProof` executes `io.ReadAll(rc)` on the replay source, followed by full JSON unmarshaling into DTOs and token tracking. Although this allocation is released before wire commit under the held decode permit, it is undeniably body-proportional at proof time.

#### Phase B: Post-Commit Wire Execution Retained Heap
- 1 MiB: **35,656 B/op** (12 allocs/op)
- 5 MiB: **35,656 B/op** (12 allocs/op)
- 20 MiB: **35,656 B/op** (12 allocs/op)
- **Slope**: **0.000% (PERFECTLY FLAT)** across 1 MiB → 5 MiB → 20 MiB.
- Retained state during execution consists exclusively of:
  - Fixed 32 KiB stream read buffer (`32,768 B`)
  - Bounded `WireRequestFacts` and `AssessmentStamp` (~`2,888 B`)
  - Temporary spill file descriptor on disk (zero payload bytes retained in Go heap)
  - No `lipapi.Call`, no message tree, and no `CloneCall`.

### 5.3 Task 19.3 Gate Verdict

- **Post-Commit Retained Wire Heap**: **PASS**. Prompt-size-dependent Go heap retention after capture and proof is completely eliminated. Retained heap is strictly bounded by `memory_spool_bytes` (64 KiB) + facts + fixed buffers.
- **Strict No-Payload-Heap Invariant (Proof Time)**: **FAILED**. Because `CompileProof` relies on `io.ReadAll` rather than the streaming hash parser built in Task 6.2, transient allocation scales with body size during the proof phase.
- **Handoff to Task 19.7 / Task 20**: The lane must not be advertised for production until `CompileProof` integrates the streaming hash parser to eliminate transient `io.ReadAll`, achieving $O(1)$ allocation throughout the entire lifecycle.
