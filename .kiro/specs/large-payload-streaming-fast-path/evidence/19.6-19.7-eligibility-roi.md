### 3.1 Primary Blocker Root Causes

1. **Full `Call` Materialization / Mutation Dependency (19 Planes, 3 Hook Chains, 6 Ports)**:
   - Request transforms, submit hooks, local turn handlers, secret guards, and pre-request handlers demand access to `lipapi.Call` or deep-cloned ASTs.
2. **Trajectory and Historical State Dependencies (4 Ports, 1 Plane)**:
   - `ConversationViewReader`, `ConversationViewTagger`, `SteeringWriterFactory`, and `terminal_decision_provider` rely on stored message items or trajectory state.
3. **Token Accounting without Streaming Wire Counter (3 Ports)**:
   - `accounting.preflight`, `accounting.stream_usage`, and `accounting.admin_count_service` require input token counts. In stock configurations, token counters only accept `lipapi.Call`.
4. **Heterogeneous Late-Route Domains (Routing Engine)**:
   - If a route override domain includes backends with incompatible body modes or differing rewrite rules, core assessment declines before `BeginTurn`.
5. **Pre-Preflight Legacy Resolver (1 Seam)**:
   - `Spec.ResolveRouteSelector` requires the full raw byte buffer before shared preflight.

## 4. Section C: Honest Wire-Mode Execution Statement

Requirement 21.6 dictates: *"At least one normal secure-session + metering production-like composition shall reach wire execution. A design that compiles but is blocked by standard normally-on components is incomplete."*

We report the exact, unvarnished state of wire mode execution across test doubles versus full production runtime composition:

### 4.1 Candidate-Path Wire Execution with Test Double Executors: PROVEN

In isolated candidate-path test suites and E2E conformance harnesses, normal secure-session and metering compositions **actually execute wire mode**:

1. **Runtime Metering & Secure Session Composition Test** (`internal/core/runtime/wire_metering_composition_test.go`):
   - `TestWireComposition_NoAccounting_ReachesWireModeAndCompletesLifecycle`:
     - Configured with live `SecureSession` manager, `CapturingTurnRecorder`, `MemoryFactRecorder`, and B2BUA Store.
     - Token accounting and preflight disabled.
     - Executes `PrepareSecureSession` → `ExecuteBeginTurn` → `RecordClientTurnWithShape` → `CaptureFrontendIngressCheckpoint` (`fe-ingress:`) → `CaptureWireBackendIngress` (`be-ingress:`) → failover attempt → widening assertion (`AssertWireAttemptNotWidened`).
     - **Verified**: Completed full wire lifecycle with **zero `lipapi.Call` retention and zero `CloneCall` invocations**.
2. **Protocol Lane E2E Conformance Tests** (`openairesponses`, `openailegacy`, `openresponses`):
   - `TestLane1E2E_SecureRecorderInput`: verified `ClientTurnShape` records normalized roles/ordinals/part-kinds through candidate pipeline.
   - `TestLane1E2E_MeteringCheckpoints`: verified `fe-ingress` and `be-ingress` checkpoints capture exact quantities (`Request=1`, `MaxOutput=4096`) under `frontendpipe.ServeHTTP`.
   - `TestLane1E2E_SessionResumeTurn2`: verified multi-turn session continuity, resume token wrapping via `SensitiveString`, and confidentiality assertion (zero resume token leakage into upstream headers or body).
   - `TestLane2E2E_Conformance` (14 tests) and `TestLane3E2E_Conformance` (15 tests) verify identical candidate wire execution.

### 4.2 Full Production Runtime Composition: ZERO WIRE EXECUTION (Honest Gap Statement)

In a standard production binary build (e.g. `cmd/lipstd` via `internal/infra/runtimebundle` and `internal/stdhttp`):

1. **No Production Assessor Composition**:
   - `internal/core/runtime.Executor` implements `ExecuteLargeBody` (`LargeBodyWireExecutor`).
   - However, **no component in `runtimebundle` or `stdhttp` implements or composes `AssessLargeBody` (`LargeBodyAssessor`)**.
   - `CandidatePrerequisites(spec)` in `internal/plugins/frontends/frontendpipe/profile.go` performs:
     ```go
     capability, ok := spec.Exec.(largebody.LargeBodyExecutor)
     ```
   - Because `runtime.Executor` does not implement `LargeBodyAssessor`, it does not satisfy `LargeBodyExecutor`. `CandidatePrerequisites` returns `(nil, false)`.
2. **Resulting Production Behavior**:
   - Every incoming request in stock `lipstd` immediately declines candidate evaluation at prerequisite check and proceeds to the **unchanged canonical read path** (`reqbody.ReadAll`).
   - Zero temporary spool files are created; zero streaming scanners are instantiated; zero wire requests are committed.
3. **Default-Off Status**:
   - `server.large_payload_fast_path.enabled` defaults to `false` (Requirement 22.1).
   - No protocol profile advertises wire support (default-off `LargePayload.Enabled` across Lanes 1, 2, 3; verified by `TestLane1E2E_WireSupportNotAdvertised`).
4. **Group 20 Gap Acknowledgment**:
   - Unifying `AuthorityAssessor`, `BackendWireProofAssessor`, `RouteOverrideAssessor`, and `runtime.Executor` into a production `LargeBodyExecutor` and wiring it into `runtimebundle.BuildHost` is the explicit remit of **Task 20.3 (Default-off production rollout)**.
   - We do not overclaim: **No full-production-runtime composition executes wire mode today.**

### 5.2 Separate Tradeoff Analysis

#### 1. Heap Savings Analysis
- **Post-Commit Execution Heap**: **Spectacular success**. Retained Go heap during provider streaming is **35,656 B/op (12 allocs/op)** with a **0.000% slope** across 1 MiB, 5 MiB, and 20 MiB. Canonical execution retained multiple full `lipapi.Call` structures, deep message item trees, and 7–9 `CloneCall` copies, leading to multi-megabyte retained heaps.
- **End-to-End Request B/op**: Measurable -38.5% to -40.6% reduction in total garbage allocated over the full request lifecycle.
- **Proof-Time Transient Heap**: **Definite failure of strict gate (Task 19.3)**. `CompileProof` uses `io.ReadAll` on the replay source, generating ~6.5x to ~7.9x payload-proportional transient allocations (6.88 MB at 1 MiB, 34.14 MB at 5 MiB, 165.53 MB at 20 MiB). While released before wire commit under the held decode permit, it violates the strict sub-payload invariant.

#### 2. CPU & Latency Tradeoff
- Fast-path end-to-end latency is approximately 1.4x to 1.6x higher than canonical transport (38.88 ms vs 26.9 ms at 1 MiB; 184.39 ms vs 116.0 ms at 5 MiB, both against 1.10 §4.7 production-like composition).
- **Latency Cause**: Proxy-side streaming capture to disk + streaming SHA-256 calculation + full JSON scanning + protocol unmarshaling in `CompileProof` must finish before upstream provider connection opens.
- As stated in Requirement 21.8, V1 optimizes for heap/GC stability and avoiding canonical AST re-marshaling, **not for TTFT**.

#### 3. File I/O & Concurrency Tradeoff
- Payloads exceeding `memory_spool_bytes` (64 KiB) spill to disk in `SpoolDir`.
- Temporary files use 0600 permissions, unpredictable names, and are deleted immediately upon completion or cancellation (0 leaked files verified in Task 19.5).
- Concurrent execution scales well (190.28 MB/s aggregate throughput across 12 cores).
- Spool budget exhaustion gracefully falls back to canonical reading with HTTP 200 (no client-visible errors).
