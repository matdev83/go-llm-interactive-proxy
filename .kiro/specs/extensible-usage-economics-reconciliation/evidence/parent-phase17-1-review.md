## Required remediation

1. **Important: writer claims repair invalid durable identity instead of rejecting it.** `internal/core/billing/v1_migration_compat.go:274–303` calls `Seal` and discards the incoming key/fingerprint. A concrete counterexample is the valid Phase 1 leg with `Fingerprint = "deadbeef"`: `ProjectHistoricalV1Leg` correctly rejects it, but `CheckHistoricalV1WriterClaim([]CallLegUsageRecord{leg}, HistoricalV1WriterVersion)` returns nil, because `Seal` recomputes the fingerprint. An empty or wrong key is similarly repaired. This is reachable from `DurableStore.CheckHistoricalV1WriterClaim` (`historical_v1_migration.go:174–193`): its existing loader reads only payload JSON and does not validate sealed identity or row metadata. The core helper also accepts two V1 legs from different calls as one ownership claim. These are source-traced counterexamples, not newly executed adversarial tests; reviewer write ownership excludes test files. Require sealed identity validation before normalization, check row key/fingerprint and requested CallID at the store boundary, and reject mixed-call sets. Anchor: task 17.1 old replay identity and explicit writer ownership; requirement 17.2, Migration Strategy step 2; the new API's own malformed/ambiguous fail-closed contract. This does not require durable epochs or actual posting integration from 17.3.

2. **Important: the exported version resolver accepts unsupported formats.** At `v1_migration_compat.go:175`, `EvidenceVersion >= EvidenceFormatVersionV2` returns V2 for version 3 (or 999) with `EvidenceProjectionV1`. Existing `CallLegUsageRecord.validate` explicitly accepts only 0 or 2. Similarly, a baseline leg with `EconomicEvidenceVersion = 1` and no dispositions is classified V1 by this resolver despite failing the existing record contract. Callers that first seal happen to reject those cases, but the exported resolver claims to resolve a durable record and is independently called and tested. Reject unknown versions and contradictory auxiliary provenance directly; add table tests covering all existing evidence-version/projection conventions. Anchor: requirement 17.2 and task 17.1 explicitly versioned compatibility, not future-format guessing.
