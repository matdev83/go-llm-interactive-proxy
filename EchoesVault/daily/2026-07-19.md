### Status / context (current facts)

- Feature `reasoning-output-preservation` is standard `lipstd` **default-on** but **model/rule-gated**. Unmatched requests are **fully inert**: after eligibility resolution, completely no-op -- no event parsing/buffering, no store I/O, no mutation, and no feature telemetry/outcomes.
- Older completed E2E spec (Chat/Anthropic-centric HTTP validation) remains **historical**. Docs/EchoesVault still treat Responses as deferred/incomplete for full fidelity -- that claim must be removed only after completion criteria below pass.
- Existing gap: OpenAI Responses **backend can replay already-canonical exact reasoning items**, but does **not ingest** provider Responses reasoning output into canonical reasoning events. Current Responses `refbackend`/`refclient` **lack stateful reasoning replay E2E**.
- Existing default-on HTTP harness is **Chat-centric** under `internal/stdhttp/reasoning_preservation_http_*`.
- `go.mod` pins `github.com/openai/openai-go/v3 v3.43.0`.
- SDK stream union supports: `response.output_item.added/done`, `response.reasoning_summary_part.added/done`, `response.reasoning_summary_text.delta/done`, `response.reasoning_text.delta/done`, `response.completed`.
- Current mapper gap: `internal/plugins/backends/openairesponses/map_events.go` ignores reasoning event types and reasoning output items.
- Current replay encoder: `internal/plugins/backends/openairesponses/invoke.go`; exact replay unit coverage in `reasoning_replay_red_test.go`, but **text/summary fallback must be removed** for exact-only posture.
- Current frontend: `internal/plugins/frontends/openairesponses/encode.go` synthesizes IDs/summary from `EventReasoningDelta`; nonstream collector retains only text.
- Canonical contracts: `pkg/lipapi/events.go`, `pkg/lipapi/reasoning.go`.
- Capture/store/restore today: `internal/plugins/features/reasoningpreservation/` (+ related `internal/reasoningreplay/`, bootstrap inject under `internal/standardplugins/`, `internal/infra/runtimebundle/`).
- Ref harness: `internal/refbackend/openairesponses/server.go`, `internal/refclient/openairesponses/client.go`, `internal/testkit/reasoninge2e/`.

### Approved decisions (do not reopen without user)

1. **Exact opaque replay only.** Preserve complete `id`, `summary`, optional `content`, and nullable/present `encrypted_content`. No summary-only fallback. No lossy synthesis.
2. **All canonical combinations**, not only Responses->Responses:
   - Chat FE / Chat BE
   - Responses FE / Chat BE
   - Chat FE / Responses BE
   - Responses FE / Responses BE
3. **Hard dialect mismatch** uses existing reject / `log_skip` controls. **No pairwise translators.** No conversion between Chat-shaped and Responses-shaped reasoning artifacts.
4. **Default-on + model/rule gating + inert unmatched** must remain. Explicit opt-in/opt-out paths stay supported.
5. **New Kiro spec required** (protocol/canonical contracts change). Requirements + design approval before code. Older completed E2E spec is historical only.

### Non-goals

- Pairwise protocol translators or Chat<->Responses reasoning conversion.
- Summary-only or text-delta synthesis as a substitute for exact Responses items.
- Provider SDK types leaking outside adapters.
- Claiming Responses production coverage before all completion criteria pass.
- Changing unrelated default-on Chat/Anthropic paths except where shared canonical contracts require coordinated extension.

**Constraints:**
